# **Software Requirements Specification (SRS)**

**Project Title:** NLP-Powered Holiday Request Prototype  
**Version:** 3.0  
**Date:** 2025-11-03

---

## **1. Context and Purpose**

A product manager needs a **web application prototype** capable of accepting **natural language requests** (in English, Dutch, and French, for v1 - English only) and converting them into travel/holiday parameters (search request parameters).  
The primary goal is to test multiple solution approaches (e.g., vector databases, structured output models, or dialog-based clarification) and **monitor performance** in terms of processing time.

The prototype is designed for different groups of stakeholders, so the interface must be **minimal, intuitive, and easy to deploy**. No corporate branding is expected.

---

## **2. Business Value**

- **Accelerate innovation testing** for NLP-based intent understanding in the travel domain.

- **Reduce time-to-market** for a production-grade natural language interface by prototyping viable architectures.

- **Enable performance benchmarking** across alternative NLP methods (LLM structured outputs, vector search, etc.).

- **Improve user experience** by analyzing where clarifications or re-prompts are needed.

- **Support multilingual interactions**, broadening the app’s global applicability.

## **4. High-Level Process Description**

### **Primary Flow**

1. **User accesses web app** (no mandatory login).

2. **User provides a voice or text input** (e.g., “I’m looking for a honeymoon hotel”).

3. **System detects language** (English/Dutch/French). Note: for v1 - English only.

4. **NLP component parses intent** and extracts the request parameters:
   
   - Holiday start date / date range (departureDate); "December 20 this year".
   
   - Number of nights (duration); "1 week"; exactly defined for v1, e.g. "2-3 nights" is out of scope.
   
   - Departure airport(s) (from); e.g. "departure from Amsterdam or Ostend"; exactly defined for v1, e.g. "Schiphol" is out of scope.
   
   - Desired destination(s) (to);  "to Spain or Italy".
   
   - Number of participants and their types; out of scope of v1.
   
   - Accommodation preferences; out of scope of v1.

5. **System validates the extracted search request parameters according to dates.json, airports.json, destinations.json and checks for missing mandatory parameters according to configuration_search.json (see fixture folder)**.

6. **System indicates that conversion is completed, shows the outcome (mandatory parameters and their values) and the result (succeeded/failed)**.

7. **Conversion completion logged**:
   
   - Timestamp
   
   - Method used (LLM, Vector DB, etc.)
   
   - Speech-to-text processor (e.g. Deepgram)
   
   - Input user utterances
   
   - Processing time
   
   - Extracted and validated search request data, along with missing parameters and invalid values if it takes place (see the example of output json)
   
   - The result of processing (succeeded/failed).

8. **System stores transaction record** in CSV (UTF-8) file.

## **6. High-Level Solution Requirements**

### **6.1 Functional Requirements**

1. **Multilingual NLP Processing:** Support English, Dutch, and French input. For v1 - English only.

2. **Voice and Text Input:** Both available from first release. Voice input can be toggled off for debugging purposes.

3. **Intent Extraction:** Identify core request entities and intents; multi-intent is out of scope of v1.

4. **Mandatory request parameters expected from users**: holiday start date/date range, either departure airport(s) (from) or desired destination(s) (to).

5. **Parameter Clarification:** Detect missing mandatory parameters or/and their invalid values, and trigger clarifications. The clarification mode is configurable: either questions are generated by LLM or predefined (see below). 
   
   | **Request parameter**         | **Condition**     | **Clarification question**                                                                             |
   | ----------------------------- | ----------------- | ------------------------------------------------------------------------------------------------------ |
   | holiday start date/date range | parameter missing | “Could you specify the desirable holiday start date or period?”                                        |
   | holiday start date/date range | invalid value     | “I am sorry we don’t have offers for this date. Could you reconsider your holiday plan?”               |
   | departure airport(s)          | parameter missing | “Could you specify the desirable departure airports?”                                                  |
   | departure airport(s)          | invalid value     | “I am sorry we don’t have anything from these airports. Could you reconsider your holiday plan?”       |
   | desired destination(s)        | parameter missing | “Could you specify  the desirable destinations?”                                                       |
   | desired destination(s)        | invalid value     | “I am sorry we don’t have any offers for these destinations. Could you reconsider your holiday  plan?” |

6. **Parameter validation rules.**
   
   | **Input request parameter** | **Input values examples**                             | **Validation rules**                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
   | --------------------------- | ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
   | Holiday start date          | “December 20 2025”, “next Sunday”, “mid December” etc | The extracted values comply with dates provided in dates.json (see checkIns array). If flexibility.isFlexibleAllowed=true, use id value where isDefault=true to calculate the date range (see configuration_search.json), unless explicitly specified by user ( “on Dec 20, 5 days flexible”). If the user explicitly specifies the date range, it should stay within the allowed values defined in flexibleList of configuration_search.json. I.e. if user specifies flexibility 2 months, the validation fails, since the maximum allowed range is +-14 days. If the user specifies the exact date without flexibility (“on Dec 20, not flexible”), provide a single-date array even if flexibility is allowed globally The system converts both user input and dates from dates.json into ISO-8601 format (YYYY-MM-DD). If ±N expansion crosses dates not present in dates.json (e.g., one bound missing), the validation fails. |
   | Departure airport(s)        | “Amsterdam, Ostend”                                   | The extracted values comply with ‘name’ property values listed in airports.json and their availability (the value does exist in the list and available=true).  If isMultiSelectAllowed=true, then the max number of airports <= maxAllowedToSelect according to the departureAirport of configuration_search.json.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
   | Desired destination(s)      | “Spain”, “Italy”                                      | The extracted values comply with ‘name’ property values listed in destinations.json and their availability (the value does exist in the list and available=true). If missing, use the one with isDefault=true.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |

The total number of participants <= maxParty (i.e. adults + children+infants)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |

Otherwise, rooms: roomsConfiguration.defaultNoOfRooms room.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
   
   The search request is valid when either (Holiday start  
   date ('departureDate') AND Departure  
   airport(s) ('from') ) OR (Holiday start  or
   date ('departureDate') AND Desired destination(s)
    ('to')) are specified correctly. 
   
   Example 1, success: "I am looking for a trip to Spain or Italy from December 20 this year." 
   
   Example 2, success: "I am looking for a trip departing from Amsterdam or Ostend from December 20 2025."
   
   Example 3, failure: "I am looking for a trip departing from Amsterdam or Ostend to Spain or Italy." - holiday start date is missing.
   
   Example 4, failure: "I am looking for a trip starting on December 20 this year." - no departure airport or destination is specified.
   
   **Validation order**: (1) language detect; (2) extract; (3) normalize to canonical codes/IDs; (4) validate against fixtures (including `available=true`, count limits); (5) enforce required-fields rule; (6) expand dates per flexibility; (7) build output; (8) log outcome.

7. Configurable Interaction Mode (see INTERACTION_MODE key): option to switch between Q&A-style dialog or direct parse (i.e. no questions, process 'as is').

8. **Data Logging:** Store conversion metadata and results in a CSV file (create if it does not exist, otherwise append).

9. The system uses settings stored in .env file in the project root.

### **6.2 Non-Functional Requirements**

| Category            | Requirement                                                                                                                                                                                                                                                                                                   |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Performance**     | Record processing time; must equal or less than the defined threshold; the threshold value is total processing time from user input (voice conversion, if toggled on, is included) to the completion of validation+render; the default value of 1 sec is defined in .env file (PROCESSING_THRESHOLD_MS=1000). |
| **Usability**       | Minimal UI using Open-WebUI for rapid adoption.                                                                                                                                                                                                                                                               |
| **Scalability**     | Must support multiple NLP engines (LLM, vector DB, LangChain).                                                                                                                                                                                                                                                |
| **Maintainability** | Modular NLP engine integration for easy A/B testing.                                                                                                                                                                                                                                                          |
| **Localization**    | For MVP all system prompts and error/clarification messages are in English only.                                                                                                                                                                                                                              |
